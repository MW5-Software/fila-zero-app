# Contas do KRONOS.net — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dar ao admin de cada cliente as telas para administrar a própria gente — usuários, perfis e permissões —, dar a cada pessoa o controle do próprio acesso, e dar à MW5 a capacidade de entrar como alguém para resolver chamado, com tudo registrado.

**Architecture:** Um model `Perfil` próprio guarda as permissões marcadas uma vez, e a pessoa entra no perfil — o `Group` do Django deixa de ser usado como vocabulário. As permissões de módulo passam a existir como linhas de `Permission`, semeadas pelo mesmo `post_migrate` que semeia os módulos, para que a tela de Perfis tenha o que oferecer. A auditoria é uma tabela append-only no banco da instalação; a personificação guarda quem era o original num cookie assinado, e cada troca é registrada.

**Tech Stack:** Python 3.13, Django 5.2 LTS, Jinja2, pytest + pytest-django.

**Spec:** `docs/superpowers/specs/2026-08-20-kronos-net-matriz-design.md`

**Entregas anteriores:** `docs/superpowers/decisoes-2026-08-20-nucleo-visual.md` e `docs/superpowers/decisoes-2026-08-20-fatia-fina.md`. **As decisões registradas ali valem aqui, e duas delas são vinculantes** — ver Global Constraints.

## O que esta entrega dá, em uma frase

O admin do cliente entra e **administra a própria equipe** — cria usuário, dá perfil, reseta senha, desativa; cria e edita perfis marcando permissões por módulo. Cada pessoa troca a própria senha e foto. A MW5 entra como alguém para ver o que a pessoa vê, e **tudo isso fica registrado**.

## O que esta entrega NÃO dá

Empresa/filial (decisão do dono: fica para depois). Prévia ao vivo na Aparência, logos pela tela, reordenar menu — são entrega 3. Gateway Oracle, rollout nas VPS — entregas seguintes.

```python
"""As permissões de módulo, como linha no banco.

`ModuloSpec.permissoes` declara `("frete.ver", "frete.editar")`. Isso é o
vocabulário do núcleo; o Django guarda permissão com sublinhado, porque
`codename` não aceita ponto. Este módulo faz a ponte: cria a linha que a tela
de Perfis oferece e que `contas.backend.permissoes_de` traduz de volta.

Roda no mesmo `post_migrate` que semeia os módulos, pelo mesmo motivo: uma
migração de tiro único deixaria as instalações existentes sem a permissão do
módulo novo.
"""

from __future__ import annotations

from plataforma.declaracao import declarados

__all__ = ["CONTENT_TYPE", "materializar"]

#: A âncora das permissões de módulo. Elas não pertencem a um model — são do
#: sistema —, e o Django exige um `ContentType`. Usamos o de `Modulo` porque é
#: o mais próximo do que elas governam.
CONTENT_TYPE = ("plataforma", "modulo")


def _rotulo(chave: str, acao: str) -> str:
    """O texto que a pessoa lê na tela de Perfis."""
    if acao == "*":
        return f"{chave}: tudo"
    return f"{chave}: {acao}"


def materializar(apps=None, using=None) -> int:
    """Cria a `Permission` faltante de cada permissão declarada.

    Além das declaradas, cria o coringa `<chave>_*` de cada módulo — a forma
    canônica de conceder o módulo inteiro, e a que faz um perfil não envelhecer
    quando a ação nova de amanhã aparecer.

    **Não apaga nada.** Módulo removido do código deixa a permissão para trás:
    apagá-la revogaria acesso de gente em vinte instalações no meio de uma
    atualização.
    """
    if apps is None:
        from django.apps import apps as apps_reais

        apps = apps_reais

    Permission = apps.get_model("auth", "Permission")
    ContentType = apps.get_model("contenttypes", "ContentType")

    gerente = Permission.objects.db_manager(using) if using else Permission.objects
    gerente_ct = ContentType.objects.db_manager(using) if using else ContentType.objects

    app_label, model = CONTENT_TYPE
    tipo, _ = gerente_ct.get_or_create(app_label=app_label, model=model)

    querem: dict[str, str] = {}
    for spec in declarados():
        querem[f"{spec.chave}_*"] = _rotulo(spec.chave, "*")
        for permissao in spec.permissoes:
            _, _, acao = permissao.partition(".")
            if acao:
                querem[f"{spec.chave}_{acao}"] = _rotulo(spec.chave, acao)

    existentes = set(
        gerente.filter(content_type=tipo, codename__in=querem)
        .values_list("codename", flat=True)
    )
    novas = [Permission(codename=c, name=n, content_type=tipo)
             for c, n in querem.items() if c not in existentes]
    gerente.bulk_create(novas)
    return len(novas)
```

```python
__all__ = ["Perfil"]


class Perfil(models.Model):
    """Um conjunto de permissões com nome, e as pessoas que estão nele.

    Existe em vez do `Group` do Django por dois motivos. O primeiro é de
    vocabulário: a tela do admin do cliente mostra `frete: ver`, não
    `plataforma.frete_ver`. O segundo é de fronteira: o `Group` carrega
    permissões de tabela do Django, que o admin do cliente não deveria
    enxergar nem conceder.
    """

    nome = models.SlugField("nome", max_length=60, unique=True)
    rotulo = models.CharField("rótulo", max_length=120)
    permissoes = models.ManyToManyField(
        Permission, verbose_name="permissões", blank=True, related_name="perfis",
    )
    usuarios = models.ManyToManyField(
        User, verbose_name="usuários", blank=True, related_name="perfis",
    )
    #: Os que o sistema cria sozinho e não deixa remover.
    do_sistema = models.BooleanField("do sistema", default=False)
    criado_em = models.DateTimeField("criado em", auto_now_add=True)

    class Meta:
        verbose_name = "perfil"
        verbose_name_plural = "perfis"
        ordering = ("rotulo",)

    def __str__(self) -> str:
        return self.rotulo


```
